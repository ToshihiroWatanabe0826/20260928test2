# V字開発ドキュメント項目定義

## 1. 目的

既存の社内ITポータルをV字モデルで整理するため、各工程の文書へ記入する情報項目と、文書間の対応付けルールを定義します。

## 2. 文書と記入項目

| 工程 | 文書 | 主な記入項目 |
|---|---|---|
| 要件定義 | `requirements/requirements.md` | 背景、目的、利用者、対象範囲、業務要件、機能要件、非機能要件、制約、受け入れ条件、対象外、要件一覧 |
| 基本設計 | `basic-design/basic-design.md` | システム構成、画面一覧、外部インターフェース、主要データ、主要フロー、エラー方針、非機能設計、要件との対応 |
| 詳細設計 | `detailed-design/detailed-design.md` | モジュール、型、関数、HTTP契約、画面制御、入力検証、状態管理、例外処理、詳細な要件との対応 |
| 単体テスト | `unit-test/unit-test-spec.md` | 対象単位、前提、テストデータ、正常・異常・境界値、期待結果、自動化状況、詳細設計との対応 |
| 結合テスト | `integration-test/integration-test-spec.md` | 結合対象、API・静的配信、データ整合、エラー連携、前提、期待結果、自動化状況、基本設計との対応 |
| システムテスト | `system-test/system-test-spec.md` | 利用者シナリオ、画面操作、業務フロー、回帰、アクセシビリティ、表示環境、受け入れ条件との対応 |

## 3. 共通の識別子

| 種別 | 形式 | 例 |
|---|---|---|
| 機能要件 | `FR-xxx` | `FR-003` |
| 非機能要件 | `NFR-xxx` | `NFR-002` |
| 制約 | `CON-xxx` | `CON-001` |
| 基本設計要素 | `BD-xxx` | `BD-004` |
| 詳細設計要素 | `DD-xxx` | `DD-006` |
| 単体テスト | `UT-xxx` | `UT-010` |
| 結合テスト | `IT-xxx` | `IT-005` |
| システムテスト | `ST-xxx` | `ST-008` |

## 4. V字の対応関係

| 左側の工程 | 右側の検証工程 | 確認する関係 |
|---|---|---|
| 要件定義 | システムテスト | 利用者の目的、機能要件、非機能要件、受け入れ条件を満たすか |
| 基本設計 | 結合テスト | 画面、API、データ、モジュール間の連携が設計どおりか |
| 詳細設計 | 単体テスト | 関数、入力検証、状態遷移、出力形式が詳細設計どおりか |

## 5. 記述上のルール

- 現在の実装から確認できる事実と、将来追加する内容を混在させません。
- 実行していないテストを実施済みと記載しません。
- 自動テストがない項目は、手動確認または未自動化として明示します。
- 要件、設計、テストケースを識別子で追跡できるようにします。
- 既存アプリに存在しない機能は、追加要件で対象範囲に明記されていない限り対象外とします。
