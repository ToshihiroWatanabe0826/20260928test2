# 既存アプリ単体テスト仕様書

> 文書の記入項目とID規則は[ドキュメント項目定義](../document-items.md)を参照してください。

## 1. 目的

詳細設計で定義した入力変換、絞り込み、状態制御、入力検証、文字列生成、ポート検証を関数単位で確認します。

## 2. 自動化方針

既存画面で使用する純粋関数は`public/portal-core.js`、サーバーポート検証は`src/server-port.ts`へ分離し、Vitestで直接検証します。DOM操作、HTTP通信、利用者シナリオは単体テストの対象外です。

## 4. 実行方法

```text
npm run test:unit
npm run test:coverage
```

標準出力・標準エラーを含むログを`docs/unit-test/evidence/`へ保存します。Coverageの対象は`public/portal-core.js`と`src/server-port.ts`です。

## 5. 完了条件

- 各ケースが独立して再実行できます。
- 正常、異常、境界値を確認します。
- 対象コマンドの終了コードが0です。
- 実行日時、対象実装Commit、コマンド、件数、Coverage、証跡ファイルを実施証跡へ記録します。
