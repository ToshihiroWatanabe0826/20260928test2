# 既存アプリシステムテスト仕様書

> 文書の記入項目とID規則は[ドキュメント項目定義](../document-items.md)を参照してください。

## 1. 目的

利用者が社内ITポータルをブラウザーで操作し、情報確認、トラブル切り分け、相談準備を完了できることを確認します。

## 2. 前提

- `npm run start`でアプリを起動できること
- PlaywrightからChromium系ブラウザーを使用できること
- `GET /api/portal`を取得できること
- メール送信は行わず、下書きとリンクだけを確認すること

## 3. 利用者シナリオ

| ID | シナリオ | 主な操作 | 期待結果 | 対応要件 |
|---|---|---|---|---|
| ST-001 | FAQから自己解決する | 検索、カテゴリ選択、FAQ展開 | 条件一致、件数更新、確認手順表示 | FR-002〜FR-005、NFR-001 |
| ST-002 | お知らせを確認する | 一覧、カテゴリ選択、詳細展開 | 新着順、絞り込み、詳細表示 | FR-006、FR-007 |
| ST-003 | 解決ナビから関連FAQを確認する | 症状選択、回答、戻る、リセット | 回答に対応する経路とFAQを表示 | FR-008〜FR-010 |
| ST-004 | 解決ナビから相談準備を行う | 結果まで進み、相談へ移動 | カテゴリ、概要、回答履歴を引き継ぐ | FR-011〜FR-013 |
| ST-005 | 不正な相談入力を修正する | 空・空白・上限超過を入力 | 下書きを作らず、日本語理由とフォーカスを表示 | FR-014 |
| ST-006 | 下書きを外部操作へ渡す | 下書き生成、コピー、メールリンク確認 | 件名・本文・`mailto:`を生成し、自動送信しない | FR-015、FR-016、NFR-006 |
| ST-007 | データ取得失敗から復旧する | API失敗、復旧、再読込 | エラーと再読込を表示し、通常操作へ復旧 | FR-018、NFR-007 |

## 4. 非機能テスト

| ID | 対応要件 | 操作 | 期待結果 |

| ST-009 | NFR-002、NFR-003 | キーボードだけで主要操作 | 操作可能で、フォーカスと状態を確認できる |

## 5. Playwright自動化

`npm run test:system`で`tests/system/existing-portal.playwright.ts`を実行します。主要シナリオの実行ログに加え、次の画面証跡を`docs/system-test/evidence/`へ保存します。

| 対象 | 画面証跡 |
|---|---|
| ST-001〜ST-002 | `baseline-faq-notices.png` |
| ST-003〜ST-006 | `baseline-guide-contact.png` |
| ST-007〜ST-015 | `baseline-quality.png` |

自動化で網羅しない手動確認がある場合は、未実施として明示します。失敗時だけの自動スクリーンショットは、主要シナリオの証跡の代替にしません。

## 6. 回帰テスト

追加開発後はST-001〜ST-015を既存機能の回帰対象とします。特に4パネルのナビゲーション、絞り込み、解決ナビ、相談下書き、入力非送信、キーボード操作、小画面表示を確認します。
