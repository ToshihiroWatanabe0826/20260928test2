# 既存アプリ要件定義書

> 文書の記入項目とID規則は[ドキュメント項目定義](../document-items.md)を参照してください。

## 1. 背景

社員がIT上の問題を自己解決できない場合、適切な情報や相談窓口を探す必要があります。既存アプリは、社内IT情報の確認、トラブルの切り分け、相談メール作成を1つのポータルで支援します。

## 2. 目的

- FAQとお知らせから必要な情報を見つけられること
- 質問形式の案内で確認手順を判断できること
- 解決しない場合に適切な窓口と相談内容を整理できること
- 秘密情報を送信せず、利用者自身がメール内容を確認できること

## 3. 想定利用者

- 社内ITサービスを利用する社員
- 問い合わせ前に自己解決を試みる社員
- 適切な相談窓口を確認したい社員

## 4. 対象範囲

- FAQ・ナレッジ
- お知らせ
- トラブル解決ナビ
- 相談窓口
- メール下書き
- ポータルデータAPI
- 稼働確認

## 5. 機能要件

| ID | 要件 | 受け入れ条件 |
|---|---|---|
| FR-001 | システムは稼働状態を返す | `GET /health`がHTTP 200と`{"status":"ok"}`を返す |
| FR-002 | システムはポータル表示に必要なデータを提供する | カテゴリ、FAQ、お知らせ、解決ナビをJSONで取得できる |
| FR-003 | 利用者はFAQを検索できる | キーワードに一致するFAQだけが表示される |
| FR-004 | 利用者はFAQをカテゴリで絞り込める | 選択カテゴリのFAQだけが表示される |
| FR-005 | 利用者はFAQの確認手順を閲覧できる | FAQを開くと順序付きの手順が表示される |
| FR-006 | 利用者はお知らせを閲覧できる | お知らせが公開日の新しい順に表示される |
| FR-007 | 利用者はお知らせをカテゴリで絞り込める | 選択カテゴリのお知らせだけが表示される |
| FR-008 | 利用者は質問に回答して確認手順を取得できる | 選択した回答に応じて質問または結果へ遷移する |
| FR-009 | 利用者は解決ナビを戻る、または最初からやり直せる | 回答履歴に従って前の質問または開始質問へ戻る |
| FR-010 | 利用者は解決結果から関連FAQを開ける | 結果に関連付くFAQを表示する |
| FR-011 | 利用者は解決結果を相談内容へ引き継げる | カテゴリ、相談概要、回答履歴が相談画面へ設定される |
| FR-012 | 利用者はカテゴリ別の相談窓口を確認できる | 担当チーム、メールアドレス、受付時間が表示される |
| FR-013 | 利用者は相談内容からメール下書きを作成できる | 正常な概要と相談内容から件名と本文が生成される |
| FR-014 | システムはメール下書きの不正入力を拒否する | 空入力、空白のみ、上限超過では下書きを生成せず理由を表示する |
| FR-015 | 利用者はメール下書きをコピーできる | 件名と本文がクリップボードへコピーされる |
| FR-016 | 利用者はメールアプリを開ける | 宛先、件名、本文を含む`mailto:`リンクを利用できる |
| FR-017 | 利用者は4つの主要画面を移動できる | URLハッシュに対応したパネルだけが表示される |
| FR-018 | 利用者はデータ読込を再試行できる | 読込失敗時にエラーと再読込操作が表示される |

## 6. 非機能要件

| ID | 要件 | 受け入れ条件 |
|---|---|---|
| NFR-001 | 画面と利用者向けメッセージは日本語とする | HTMLの言語と表示文言が日本語である |
| NFR-002 | キーボードで主要機能を操作できる | ナビ、検索、解決ナビ、フォーム、ボタンをキーボードで操作できる |
| NFR-003 | 状態とエラーを支援技術へ通知する | 状態通知とエラーに適切なARIA属性がある |
| NFR-004 | PCと小画面で利用できる | 900px以下と600px以下でレイアウトが調整される |
| NFR-005 | ライト・ダークテーマへ対応する | OS設定またはURL指定に応じて配色が変わる |
| NFR-006 | 相談内容をサーバーへ保存・送信しない | 下書き生成がブラウザー内で完結する |
| NFR-007 | ポータルデータ取得の長時間待機を避ける | 10秒で取得を中断し、再試行を案内する |
| NFR-008 | 既存データを読取操作で変更しない | 複数回取得しても同じ内容を返す |

## 7. 制約

| ID | 制約 |
|---|---|
| CON-001 | サーバーはNode.js、TypeScript、Expressで構成する |
| CON-002 | 画面はHTML、CSS、JavaScriptで構成する |
| CON-003 | データベースと利用者認証は使用しない |
| CON-004 | ポータルデータはサーバー内の固定データとする |
| CON-005 | 相談先には演習用の`example.com`を使用する |
| CON-006 | メールは実送信せず、下書きと`mailto:`リンクだけを生成する |

## 8. 対象外

- 問い合わせの登録と保存
- 問い合わせ一覧・詳細
- 優先度、担当者、対応状態の管理
- 利用者認証と権限管理
- 外部データベース
- 外部サービスへのAPI接続
- メールの自動送信

## 9. 要件と検証工程

| 要件 | 主な検証 |
|---|---|
| FR-001、FR-002 | 結合テスト、システムテスト |
| FR-003〜FR-018 | システムテスト |
| NFR-001〜NFR-005 | システムテスト |
| NFR-006〜NFR-008 | 結合テスト、システムテスト |
